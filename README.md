# 📱 Medibuddy Mobile Application

## 1. ภาพรวมโปรเจค
**Medibuddy** เป็นแอปพลิเคชันมือถือที่พัฒนาขึ้นด้วยเทคโนโลยี Flutter สำหรับการรวบรวมและแจ้งเตือนตารางการทานยาให้ผู้ใช้ตรงตามเวลาที่กำหนด แอปถูกออกแบบให้เป็นตัวช่วยส่วนตัวที่ช่วยเฝ้าระวังวินัยการดูแลสุขภาพและป้องกันการลืมทานยาได้อย่างมีประสิทธิภาพ

**ฟีเจอร์หลัก (Key Features):**
- **การติดตามยา (Medication Tracking):** บันทึกรายชื่อยา ขนาดยา และรายละเอียดของใบสั่งแพทย์
- **การแจ้งเตือน (Notifications):** แจ้งเตือนเวลากินยาแบบ Real-time ตามตารางที่วางไว้
- **การยืนยันการทานยา (Intake Confirmation):** สามารถกดตอบรับได้ว่า ทานแล้ว, ข้ามยา, หรือขอเลื่อนเวลากินออกไป (Snooze)
- **การบันทึกหมายเหตุ (Note Log):** อนุญาตให้ผู้ใช้คอมเมนต์เหตุผล เช่น ทำไมถึงไม่ได้ทานยา
- **Text-to-Speech (TTS):** มีปุ่มลำโพงให้อ่านข้อความชื่อยาและปริมาณด้วยเสียง เพื่อช่วยอำนวยความสะดวก
- **OCR สแกนฉลากยา:** ดึงข้อความและชื่อยาอัตโนมัติจากการเปิดกล้องส่องฉลาก
- **โปรไฟล์ผู้ใช้ (Profile Management):** รองรับระบบบัญชีหลายโปรไฟล์ เหมาะสำหรับผู้ที่ต้องดูแลตารางกินยาให้กับคนหลายคนในครอบครัวผ่านเครื่องเดียว

## 2. เทคโนโลยีที่ใช้
แอปพลิเคชันนี้ใช้ Framework และแพ็กเกจมาตรฐานต่างๆ ดังนี้:

- **Flutter & Dart:** เฟรมเวิร์คและภาษาหลักที่ใช้ในการสร้าง UI และ Mobile Application แบบ Cross-Platform
- **Dio:** แพ็กเกจที่ใช้จัดการ HTTP Requests เพื่อเชื่อมต่อและคุยกับ API หลังบ้าน รวบถึงช่วยดักจับดึง Token ผ่าน Interceptor
- **flutter_tts:** (Text-to-Speech) ช่วยในระบบเปลี่ยนข้อความยาให้กลายเป็นเสียงบรรยาย (มีประโยชน์ต่อหน้าการยืนยันการกินยา)
- **firebase_messaging:** จัดการโครงข่าย Cloud Messaging สำหรับรับคำสั่งการแจ้งเตือนต่างๆ 
- **flutter_local_notifications:** ใช้ยิงแจ้งเตือน Local Pop-up ภายในแอปพลิเคชันโดยตรงสำหรับแจ้งเตือนให้ตรงชั่วโมง
- **google_mlkit_text_recognition & camera:** แพ็กเกจระบบ Machine Learning ร่วมกับตัวกล้องหลัก ใช้เพื่อทำ OCR อ่านฉลากยาให้กลายเป็นตัวอักษร
- **flutter_dotenv:** โหลดและครอบคลุมตัวแปรความลับ เช่น `API_BASE_URL` หรือคีย์ต่างๆ ผ่านไฟล์ `.env`
- **shared_preferences & flutter_secure_storage:** พื้นที่จัดเก็บข้อมูลฝังในเครื่อง (Local Storage) เพื่อจัดเก็บสถานะ Profile ปัจจุบัน และตั๋ว Token ยืนยันตัวตนต่างๆ อย่างปลอดภัย

## 3. โครงสร้างโปรเจคแบบละเอียด
แอปนี้จัดระเบียบโครงสร้างแบบแยกส่วนการทำงาน (Modular / Feature-Based) ออกจากกันเพื่อง่ายต่อการพัฒนาและต่อยอด:

- **`lib/`**: โฟลเดอร์ใจกลางของโปรเจค ที่รวมโค้ด Dart ทั้งหมด
  - **`main.dart`**: จุดเริ่มต้นคลาสหลัก (Entry point) เป็นศูนย์รวมตั้งค่า Theme, ผูก Provider, และเตรียมกลไก Notification และ Router
  - **`add_medicine/`** (ส่วนงานบันทึกยาเข้าระบบ)
    - `create_medicine_profile.dart`: ใช้ออกแบบและสร้างโปรไฟล์/รูปภาพของยาตัวใหม่
    - `search_system_medicine.dart`: ระบบค้นหาชื่อยาจากฐานข้อมูลกลาง
    - `link_medicine.dart`: ใช้จับคู่ผูกยาเข้ากับประวัติผู้ใช้
    - `summary_medicine.dart`: ช่วยคำนวณและสรุปข้อมูลของยาก่อนบันทึก
    - `medicine_list_screen.dart`, `request_medicine_screen.dart`: จัดการการโชว์รายการยาและขอเพิ่มฐานข้อมูลยาใหม่
  - **`alarm_medicine/`** (หน้าต่างตอบสนองการทานยา)
    - `alarm_screen.dart`: โชว์หน้าเต็มตั้งรับเมื่อแอปได้เวลาทานยา (แจ้งเตือนดัง)
    - `confirm_action.dart`: การยืนยันสถานะหลังเตือน ควบคุมปุ่มกินยา เลื่อน ข้ามยา รวมถึงเรียกใช้ TTS (`flutter_tts`) อ่านออกเสียงชื่อยา
  - **`authen_pages/`** (ส่วนงานล็อกอินและรหัสผ่าน)
    - `login_screen.dart`, `signup_screen.dart`: หน้าต่าง UI สำหรับเข้าสู่ระบบและผู้เริ่มใช้
    - `otp_verification_screen.dart`: การกรอกรหัสลับ 6 หลัก (OTP)
    - `forget_password.dart`: จัดการการคืนรหัสผ่าน
  - **`export_pdf/`** (ทำเอกสารทางการแพทย์)
    - `history.dart`: หน้าประวัติส่วนตัวเตรียมตัวก่อนส่งออกเอกสาร
    - `medicine_plan_pdf.dart`: สร้างไฟล์เอกสาร PDF จัดเรียงโครงสร้างข้อมูล
  - **`home_pages/`** (หน้าจอสรุปภาพรวม)
    - `home_screen.dart`: หน้าโฮม รวบรวมสถิติรายวัน มีตัวแปรจัดการคลาสเกี่ยวกับ BottomBar เพื่อแสดงตารางชีวิต
  - **`medication-tracking/`** (ระบบผู้ดูแล/ครอบครัว)
    - `following.dart`, `follower.dart`, `add_follower.dart`: ฟีเจอร์ที่มอบสิทธิให้ผู้ใช้อื่นเข้ามาเช็คสถานะการทานยาแทน เพื่อช่วยคนในครอบครัว
    - `following_history.dart`, `following_regimen.dart`: ใช้ส่องประวัติและตารางรักษาย้อนหลังของคนรอบตัวเรา
  - **`Model/`** (แม่แบบข้อมูล/Data Contract)
    - `medicine_model.dart`: เก็บโครงสร้างอธิบายข้อมูลของตัวยา (อาทิ ชื่อยา, รูปแบบยา, สรรพคุณ, ปริมาณคงเหลือ) เพื่อใช้อ้างอิงรับส่งรายการยาจาก Backend
    - `medicine_regimen_model.dart`: คลาสจัดการสูตรหรือตารางแผนการทานยา (Regimen) ที่ผูกกับตัวยา รับจัดการเงื่อนไขรอบเวลา (เช่น ช่วงเวลา, ก่อน/หลังอาหาร, กินกี่วัน, ความถี่)
    - `profile_model.dart`: กำหนดโครงสร้างข้อมูลอัตลักษณ์ตัวผู้ใช้หลัก หรือรายชื่อผู้ป่วยในความดูแล (เช่น ชื่อ, ไอดีประจำตัว, รูปภาพโปรไฟล์)
    *(ไฟล์ในโหมดนี้ทำหน้าที่หลักคือเป็นพิมพ์เขียว (Blueprint) คอยรับและถอดรหัสข้อมูล JSON จาก Server ออกมาเป็น Dart Class เพื่อให้ส่งไปแสดงผลบน UI ได้ง่าย)*
  - **`OCR/`** (ระบบประมวลผลภาพจากกล้องสแกนฉลากยา)
    - `camera_ocr.dart`: หน้าจัดการฮาร์ดแวร์กล้องหลักของโทรศัพท์ เพื่อคอยเปิดและรับภาพสด (Camera Stream)
    - `ocr_camera_frame.dart`: ใช้สร้าง UI สี่เหลี่ยมสำหรับกำหนดกรอบข้อความบนหน้าจอ เพื่อบังคับโฟกัสผู้ใช้ให้เล็งตรงจุดฉลากยา
    - `ocr_image_cropper.dart`: ระบบทำการครอปตัดรูป (Crop) ที่สแนปมาให้เหลือแต่ตรงกรอบ เพื่อลดส่วนเกินรอบข้างและเพิ่มความแม่นยำก่อนวิเคราะห์
    - `ocr_result_page.dart`: หน้าต่างโชว์ผลลัพธ์หลังวิเคราะห์ภาพเสร็จ โดยคัดข้อความแปลงเป็นคีย์เวิร์ด และมีปุ่มให้กดเพื่อเติมข้อมูลยา
    - `ocr_text_service.dart`: ส่วนสมองกล (Service) ที่ทำหน้าที่ยิงใช้งาน Machine Learning (`google_mlkit`) สำหรับแปลค่า Pixels ในภาพให้กลายเป็นตัวอักษรจริง
  - **`profile_pages/`** (การบริหารอัตลักษณ์ผู้ใช้)
    - `create_profile_screen.dart`, `select_profile.dart`, `library_profile.dart`, `buddy.dart`: การสลับโปรไฟล์เพื่อดูแลผู้ป่วยคนอื่น ๆ ภายใต้ล็อกอินไอดีเดียว
  - **`select_medicine/`** (ระบบอ้างอิงและค้นหา)
    - หน้าต่างฐานข้อมูลยา สำหรับจับคู่เชื่อม (Link) รายการยาเข้าไปยังตารางแจ้งเตือนการทานยาแบบลูป (Regimen)
  - **`services/`** (แกนกลางสำหรับคุยกับ Backend โดยตรง)
    - `authen_api.dart`: ไฟล์หลักที่รวบรวมฟังก์ชันการยิง Request เข้าสู่ระบบ/สมัครสมาชิก/กู้คืนรหัสไปยัง Backend โดยตรง
    - `auth_manager.dart`: ตัวจัดการเช็คตั้งค่า (Factory) ช่วงเปิดแอป เพื่อเลือกว่าจะใช้ระบบ Login แบบใหม่ (Custom Backend) หรือระบบเก่า (Supabase) จากค่าใน `.env`
    - `token_manager.dart`: ระบบบริหารตั๋วเข้าใช้งาน (Token Lifecycle) ใช้ `flutter_secure_storage` ในการเก็บ Refresh Token อย่างปลอดภัย มีกลไก Single-Flight ช่วยแอบต่ออายุ (Refresh) Token ให้ล่วงหน้าหากใกล้หมดอายุ และสั่งเตะผู้ใช้กลับหน้า Login หาก Session หมดอายุถาวร
    - `auth_interceptor.dart`: ดักจับ (Intercept) Request ทุกเส้นทางเพื่อคอยแนบ Access Token ใส่ HTTP Header ให้โดยอัตโนมัติ
    - `device_token_service.dart`: จัดทะเบียน Notification สัญจรผ่าน FCM ของ Firebase
    - `medicine_api.dart`, `profile_api.dart`, `log_api.dart`, `regimen_api.dart`, `follow_api.dart`: รวมคำสั่ง HTTP แยกตามโมดูล รับส่งข้อมูลฝั่ง Server
  - **`set_remind/`** (ตั้งโปรแกรมและกำหนดตารางแจ้งเตือนการทานยา)
    - `setRemind_screen.dart`: หน้าต่าง UI หลักสำหรับให้ผู้ใช้กรอกฟอร์มตั้งค่าแผนการทานยาแบบละเอียด (Regimen) โดยมีตัวเลือกให้กำหนดคิววันเริ่ม/สิ้นสุด, ตั้งค่าความถี่ (ทุก X ช่วโมง/วัน/สัปดาห์), และการรับประทานพร้อมมื้ออาหาร
    - `remind_list_screen.dart`: หน้าโชว์รายการตารางการแจ้งเตือนทั้งหมดที่ถูกสร้างไว้ (Regimen List) ใช้ดูภาพรวมและสามารถกดเข้าไปแก้ไขหรือลบตารางยาที่จัดไว้ได้
    - `setFuctionRemind.dart`: ศูนย์รวมฟังก์ชันตัวช่วย (Utility functions) มีหน้าที่คำนวณและประมวลผลตรรกะเงื่อนไขการแจ้งเตือนที่มีความซับซ้อน เช่น แปลงตัวแปร `MealTiming` (ก่อนอาหาร, หลังอาหาร, พร้อมอาหาร) ไปกลับให้เป็น JSON Payload ตามโครงสร้างที่ API หลังบ้านกำหนดไว้ 
  - **`user_request/`** (แจ้งเตือนผู้รับคำเชิญดูแล)
    - `user_request_screen.dart`: หน้าต่างจัดการคำขอเพื่ออนุมัติ (Approve) สิทธิในการแชร์ประวัติการทานยา
  - **`widgets/`** (ขุมพลังชิ้นส่วน UI สามารถใช้งานซ้ำ - Reusable UI Components)
    - `bottomBar.dart`: แถบเมนูปุ่มนำทางด้านล่างของจอ (Bottom Navigation) คอยควบคุมการเปลี่ยนหน้าและขยายขนาดปุ่ม Home เป็นหลัก
    - `app_drawer.dart`: แผงซ่อนเมนูด้านข้างที่เลื่อนออกมาจากขอบจอซ้าย (Hamburger Menu) เก็บปลั๊กอินอย่าง "ออกจากระบบ" หรือรายละเอียดโปรไฟล์
    - `toast_helper.dart`: ตัวเรียกป๊อปอัพโชว์ข้อความแจ้งเตือนสั้นๆ ชั่วคราว (Toast) ที่ลอยขึ้นมาและหายไปเองโดยไม่ขัดจังหวะผู้ใช้ 
    - `comment.dart`: กล่องโครงสร้างหน้าต่าง (Modal) สำหรับให้ผู้ใช้เปิดขึ้นมาพิมพ์กรอกหมายเหตุ เวลาต้องการเขียนเหตุผลในการข้ามยา
    - `profile_widget.dart`: แม่แบบสำหรับครอบจัดรูปทรงกรอบรูปภาพ Avatar และชื่อโปรไฟล์แต่ละบัญชี (ดีไซน์ตายตัว) เพื่อให้เอาไปวางแปะในหน้าผู้ติดตามหรือหน้าล็อกอินได้ทันที
    - `login_button.dart`: อะไหล่ปุ่มกดที่มีดีไซน์เฉพาะประจำแอป (เช่น ปุ่มเข้าสู่ระบบด้วยอีเมล, แบบปุ่ม Google) สกัดไว้เพื่อไม่ให้โค้ด UI ในหน้าหลักรก และปรับแก้สีสันปุ่มได้จากที่เดียว

- **`android/`**: โฟลเดอร์เจาะจงเฉพาะในฝั่งเนทีฟ Android รวมข้อมูลเกี่ยวกับ OS
  - `android/app/build.gradle.kts`: ไฟล์ตั้งค่า Config ควบคุมเวอร์ชันการ Build ของ Android รวมถึง SDK Version, Package Name, และ Native Dependencies
  - `android/app/src/main/res/drawable/launch_background.xml`: สคริปต์กำหนดพื้นหน้าจอชั่วคราวระหว่างแอปพลิเคชันกำลังบูตตอนเปิดใช้งาน (Splash screen layer)
  - `android/app/src/main/res/raw/`: ที่เก็บไฟล์ทรัยพยากรดิบสำหรับ Android เช่น ไฟล์เสียงกริ่งกระดิ่ง Custom แจ้งเตือนให้กินยาแบบพิเศษ

- **`assets/`**: พื้นที่ส่วนกลางไว้ฝากสินทรัพย์ภาพ รูปแบบแมวลอตเต้, ตราโลโก้, อนิเมชัน JSON, และฟอนต์ที่ใช้ในแอปพลิเคชัน

- **`.env`**: ไฟล์ตัวแปรความลับซึ่งคุณต้องเขียนขึ้นมาเองในเครื่อง (ไม่ควรพุชขึ้น Git) สำหรับเสียบค่า `API_BASE_URL` หรือ Token หลังบ้าน

- **`pubspec.yaml`**: รายการสั่งขับเคลื่อน Flutter ประกอบรวมไปด้วยชื่อตัวแอปพลิเคชัน รายการเวอร์ชันแพ็กเกจทุกตัว และประกาศพาร์ทของ Assets ไฟล์ไหนที่อนุญาตให้โค้ดไปดึงมาใช้งาน

## 4. ความต้องการของระบบ
เพื่อเตรียมความพร้อมในการรันโปรเจค ให้ตรวจสอบว่าระบบของท่านมีสิ่งต่อไปนี้ครบถ้วน:
- **Flutter SDK:** ล่าสุดในสาย 3.5.0 หรือสูงกว่า
- **Dart SDK:** เป็นตัวที่ผูกพัสดุมากับ Flutter SDK ดังกล่าว
- **IDE Environments:** อนุญาตให้ใช้ Android Studio (สะดวกในฝั่งไลบรารี) หรือ Visual Studio Code (ที่ติดตั้ง Official Flutter Extension)
- **เครื่องทดสอบ (Testing Device):** แนะนำให้พ่วงเครื่องโทรศัพท์โทรศัพท์จริงในการ Build มากกว่าใช้ Simulator เสมือน เนื่องจากฟีเจอร์กล้อง (OCR) และ Push Notification Local จะตอบสนองและประมวลผลบนฮาร์ดแวร์จริงได้เสถียรกว่ามาก
- **Android SDK:** หากเป็นการรันฝั่งแอนดรอยด์ SDK Compile ต้องเป็นเวอร์ชัน 34

## 5. วิธีติดตั้งและรันโปรเจค

**ขั้นตอนที่ 1: คัดลอกโปรเจค (Clone Repository)**
ดาวน์โหลดโค้ดหลักของระบบผ่าน Terminal ไปยังพื้นที่ที่ต้องการทำการพัฒนา
```bash
git clone <repository_url>
cd medibuddy
```

**ขั้นตอนที่ 2: ดาวน์โหลดและติดตั้ง Dependencies**  
รอให้ Flutter จัดการกวาดไลบรารีทุกชิ้นที่ระบุอยู่ในไฟล์ `pubspec.yaml`
```bash
flutter pub get
```

**ขั้นตอนที่ 3: ตั้งค่าไฟล์ Configuration สำหรับ Environment**  
สร้างไฟล์ชื่อ `.env` เปล่า ๆ ไว้ที่ระดับนอกสุดของโฟลเดอร์แอปมือถือ จากนั้นกรอกข้อมูล URL API หลักของเซิร์ฟเวอร์หลังบ้าน
```bash
API_BASE_URL=https://<domain-backend-ของโปรเจค>
```

**ขั้นตอนที่ 4: สั่งรันแอปพลิเคชัน (Run the App)**  
พ่วงสายเข้าเครื่องจริง (หรือเปิด Emulator) แล้วพิมพ์สคริปต์ด้านล่างนี้ ระบบจะจูนขึ้นเป็น Mobile Application
```bash
flutter run
```
